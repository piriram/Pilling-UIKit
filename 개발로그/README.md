# 개발로그 운영 가이드

## 목적

이 폴더의 개발로그는 단순 작업 기록이 아니다. 나중에 포트폴리오, 면접 답변, 회고에 재사용할 수 있도록 경험을 재해석해서 자산화하는 문서다.

즉, 이 로그는:

- 오늘 무엇을 했는지 적는 용도
- 왜 그 작업이 필요했는지 남기는 용도
- 결과를 변화와 수치로 남기는 용도
- 나중에 경험노트와 필살기 후보로 승격시키는 재료를 쌓는 용도

## 기본 구조

개발로그는 아래 구조로 쓴다.

```text
결론(What / Product)
-> 배경(Why / 3C)
-> 실행(How / 4P)
-> 배운 점 / 다음 액션
```

## 최소 로그 항목

작업 종료 시 최소 아래 4가지는 남긴다.

- 무엇을 만들었는가
- 왜 필요했는가
- 무엇을 했는가
- 다음 액션 또는 배운 점

## 파일 작성 규칙

- 파일명: `YYYY-MM-DD.md`
- 하루에 여러 번 써도 같은 파일에 누적
- 큰 전환점이 있으면 `## 세션 N`으로 나눈다
- 복사용 템플릿은 `000_TEMPLATE.md`를 사용한다

## 좋은 로그 기준

- 수치화: 가능하면 절대값보다 변화량을 쓴다
- 구체화: 상황이 눈에 그려지게 적는다
- 행동화: 내가 실제로 취한 액션을 동사로 적는다

## 추천 작성 타이밍

- 기획 구조를 확정했을 때
- 중요한 설계 결정을 했을 때
- 화면, 로직, 위젯, 서버 연동 같은 핵심 결과물이 나왔을 때
- 문제를 해결한 직후
- 하루 마감 직전

## 주의

- 단순 나열형 로그로 끝내지 않는다
- “열심히 했다” 같은 표현은 피한다
- 나중에 면접에서 그대로 말할 수 있는 문장인지 확인한다
