# 개발로그 - 2026-05-08

## 세션 1. 서버 연동 문서와 작업 운영 규칙 정리

한 줄 요약:
- 서버 기반 알림 통합을 준비하기 위해 API 가이드와 AI 공통 운영 규칙, 개발로그/문서 저장 규칙을 프로젝트에 추가했다.

## 1. 결론 (What / Product)

- 오늘 만든 결과물: `PILLING_SERVER_API_GUIDE.md`, `AI_GUIDE.md`, `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, 개발로그 운영 문서와 템플릿
- 전/후 변화: 서버 연동 작업이 구두 설명이 아니라 문서화된 API 기준과 AI 공통 운영 규칙, 이슈 기반 브랜치 규칙 위에서 진행되도록 정리했다
- 수치 또는 범위: 서버 연동 API 6개 엔드포인트와 AI 운영 규칙 8개 섹션을 문서화했다

## 2. 배경 (Why / 3C)

### Customer

- 누구를 만족시켜야 했는가: 서버 기반 알림을 구현할 iOS 클라이언트 작업자와 이후 유지보수할 미래의 나
- 그들이 원하는 것은 무엇이었는가: 어떤 URL, 인증 헤더, endpoint, 브랜치/이슈 흐름, AI 작업 규칙을 따라야 하는지 명확한 기준

### Company

- 프로젝트의 현재 목표: Pilling 알림을 로컬 알림 중심에서 서버 기반 조건형 알림 구조로 확장
- 해결해야 할 문제: 서버 repo와 UIKit repo가 섞이지 않도록 하고, iOS 연동 기준과 AI별 작업 규칙이 분산되지 않게 정리해야 했다
- 내 기여 지점: API 가이드와 AI 공통 운영 규칙을 현재 repo에 맞게 정리했다

### Competitor

- 참고한 기준 / 레퍼런스: `idea_월급날앱` 프로젝트의 개발로그와 문서 저장 운영 방식
- 기존 방식의 한계: Pilling repo에는 개발로그와 문서 저장 규칙이 명확히 없었고, Claude/Codex/Gemini 규칙이 분산될 수 있었다
- 이번에 선택한 방향: `AI_GUIDE.md`를 단일 source of truth로 두고, 각 AI별 진입 파일은 이 문서를 참조하도록 정리했다

## 3. 실행 (How / 4P)

### Product

- 실제로 만든 것: 서버 API 연동 가이드, AI 공통 가이드, AI별 진입 파일, 개발로그 README, 개발로그 템플릿
- 문서 / 화면 / 로직 / 구조 중 무엇이 생겼는가: 서버 통합 작업의 시작 기준, AI별 규칙 참조 구조, 이후 작업 기록 방식이 생겼다

### Price

- 만족 신호: 다음 서버 연동 구현 시 API 스펙과 작업 브랜치 규칙을 다시 묻지 않아도 된다
- 구현 부담 감소: endpoint, 인증, 오류 응답, iOS 호출 흐름을 한 파일에서 확인할 수 있다
- 추후 재사용 가치: PR 본문, 구현 체크리스트, AI 작업 인수인계, 면접/포트폴리오 설명으로 재사용 가능하다

### Place

- 적용 위치: Pilling UIKit repo의 루트 AI 문서/API 문서와 `개발로그/` 폴더
- 어떤 흐름에서 쓰이는가: 서버 알림 통합 기능 개발, PR 작성, 작업 종료 루틴

### Promotion

- 공유/정리/전달 방식: Git 문서와 개발로그로 남겨 repo 안에서 바로 참조 가능하게 했다
- 이후 누가 바로 활용할 수 있는가: iOS 클라이언트 작업자와 Claude/Gemini/Codex 기반 작업 에이전트

## 4. 3화 점검

### 수치화

- 서버 API endpoint 6개, 공통 에러 4종, AI 운영 규칙 8개 섹션을 문서화했다

### 구체화

- `X-API-Key` 인증, `POST /users`, device token 갱신, 약 등록, 복용 기록 호출 흐름을 iOS 연동 순서로 정리했다

### 행동화

- 참조 repo의 운영 규칙을 비교하고 Pilling에 맞게 `AI_GUIDE.md` 중심 규칙과 개발로그 템플릿으로 반영했다

## 5. 배운 점 / 인사이트

- 기능 구현 전에 API 문서, 이슈, 브랜치 규칙을 먼저 고정하면 이후 커밋과 PR 범위가 흔들리지 않는다
- 서버 코드는 별도 repo로 유지하고, UIKit repo에는 클라이언트 연동 기준과 AI 공통 운영 규칙만 남기는 편이 안전하다
- AI별 규칙 파일은 진입점으로만 두고 실제 규칙은 하나의 문서에 모아야 장기적으로 drift가 줄어든다
